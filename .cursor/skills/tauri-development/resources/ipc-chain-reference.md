# Tauri IPC Chain — Complete Reference

Every Rootstock feature that crosses the Rust/frontend boundary follows this exact 5-step chain.
Reference this document in executor briefs: "Follow the IPC chain in tauri-development/resources/ipc-chain-reference.md."

---

## The Chain

```
commands.rs          → defines the Tauri command (Rust, async fn)
lib.rs               → registers in both macros (two places)
bindings.ts          → auto-generated by tauri-specta on debug build (do not hand-edit)
lib/tauri/foo.ts     → hand-written typed wrapper using invokeCommand()
+page.svelte         → calls the wrapper function
```

---

## Step 1: Rust Command (`src-tauri/src/commands.rs`)

```rust
#[tauri::command]
#[specta::specta]
pub async fn graft_vault_store_credential(
    service: String,
    secret: String,
    description: Option<String>,
) -> Result<VaultCredentialDto, String> {
    let store = crate::credential_proxy::StrongholdCredentialStore::default();
    store
        .store_service_credential(
            &service,
            &secrecy::SecretString::from(secret),
            description.as_deref(),
        )
        .map(VaultCredentialDto::from)
        .map_err(|error| error.to_string())
}
```

**Rules:**
- Return type is `Result<T, String>` where T is a `#[derive(Serialize, specta::Type)]` struct.
- `#[tauri::command]` and `#[specta::specta]` are BOTH required — specta generates the TS binding.
- For commands needing app state: add `state: tauri::State<'_, Arc<TrayRuntime>>` as first arg.
- Error type is always `String` (not a custom error type) for IPC commands.

## Step 2: Registration in `src-tauri/src/lib.rs` (TWO macros, both required)

Both the release macro (`rootstock_invoke_handler!`) and the debug/specta macro (`rootstock_collect_commands!`) must have the command. They share the same list:

```rust
// In rootstock_invoke_handler! (non-cfg block, ~line 64)
tauri::generate_handler![
    // ...existing commands...
    commands::graft_vault_store_credential,  // ADD HERE
]

// In rootstock_collect_commands! (#[cfg(debug_assertions)] block, ~line 124)
tauri_specta::collect_commands![
    // ...existing commands...
    commands::graft_vault_store_credential,  // AND HERE (same name)
]
```

**Omitting from either macro causes a silent failure:** the release build works but TS bindings don't generate, or vice versa.

## Step 3: Generated binding (`app/frontend/src/lib/bindings.ts`)

**Do not edit this file.** It is auto-generated when the Rust binary runs in debug mode
(`export_bindings_if_needed()` in `lib.rs::run()`). After adding a command and building,
this file updates automatically.

The generated shape looks like:
```typescript
async graftVaultStoreCredential(
    service: string,
    secret: string,
    description: string | null
): Promise<Result<VaultCredentialDto, string>> {
    // ...TAURI_INVOKE wrapper...
}
```

Note: specta wraps in `{ status: 'ok', data: T }` — the hand-written wrapper (Step 4) bypasses this.

---

## Step 4: Hand-written typed wrapper (`app/frontend/src/lib/tauri/vault.ts`)

**Always use `invokeCommand<T>()`, never call `invoke()` directly.**
`invokeCommand` adds the 30-second timeout and Tauri context guard.

```typescript
import { invokeCommand } from '$lib/api/transport';
import type { VaultCredentialDto } from '$lib/bindings';

export function storeVaultCredential(
    service: string,
    secret: string,
    description: string | null
): Promise<VaultCredentialDto> {
    return invokeCommand<VaultCredentialDto>('graft_vault_store_credential', {
        service,
        secret,
        description,
    });
}
```

**Rules:**
- The command name string must match the Rust function name EXACTLY (snake_case).
- Arg object keys must match Rust parameter names EXACTLY.
- Return type `T` is the TS equivalent of the Rust return `Ok(T)` — not the `Result` wrapper.
- Export from this file; import in `.svelte` pages via `$lib/tauri/vault`.

## Step 5: Usage in `.svelte` (`+page.svelte`)

```svelte
<script lang="ts">
  import { storeVaultCredential } from '$lib/tauri/vault';
  import { isTauri } from '$lib/api/transport';
  import { toErrorMessage } from '$lib/errors';
  import { toast } from '$lib/ui';

  async function saveCredential() {
    if (!isTauri) return;
    try {
      const result = await storeVaultCredential(service, secret, description || null);
      toast.success(`Credential '${result.service}' stored.`);
    } catch (err) {
      toast.error(toErrorMessage(err));
    }
  }
</script>
```

**Rules:**
- Always guard with `if (!isTauri) return` before any IPC call.
- Use `toErrorMessage(err)` from `$lib/errors` — not `String(err)` or `.message`.
- Use `toast.success` / `toast.error` for operation feedback.
- Error toasts do not auto-dismiss (see interaction-design skill).

## Quick Reference — Common Patterns

| Need | Pattern |
|---|---|
| Command with no state | `async fn my_cmd(arg: String) -> Result<MyDto, String>` |
| Command with TrayRuntime | `async fn my_cmd(state: tauri::State<'_, Arc<TrayRuntime>>, ...) -> Result<...>` |
| Command with CloudSyncState | `async fn my_cmd(state: tauri::State<'_, CloudSyncState>, ...) -> Result<...>` |
| Optional arg from TS | Rust: `option_arg: Option<String>`, TS: `option_arg: string \| null` |
| Void return | `-> Result<(), String>`, TS wrapper returns `Promise<void>` |
